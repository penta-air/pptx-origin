# design-system/default/DESIGN_SYSTEM.md

`default` ブランドのデザインシステムスペック。`design-system/default/components.js` が実装する定型スライドの視覚実現と、`pptx-build` が構成案ごとに自由設計するスライドの両方が、ここに書くルールに従う。定型スライドの名称・用途・`content`フィールド契約自体はブランドに依存せず `.agents/docs/fixed-primitives-contract.md` で定義されている。

色を変更した場合は `design-system/default/color-definition.json` を編集し、`node design-system/generate-theme.js default` → `node design-system/default/components.js` の順に再実行し、`design-system/default/preview.pptx` を再生成すること(デザインシステムのルール自体を作り直す場合は `pptx-design-system-init` Skill を再度実行する)。

## 視覚言語: Bold Bento(`default` ブランドの選択)

`default` は「塗り面(セル)を情報の単位として使う」という一貫した視覚言語で統一する。角丸・影は一切使わず、すべての区画は直角の塗りつぶし矩形として表現する。

- **アンカーセル**(ブランドプライマリカラーの濃色塗り、文字は`colors.bgDefault`=白)と**淡色セル**(`colors.bgAccent`の塗り)の2種類を使い分ける。
- アンカーセル(濃色)を使うのは、**構造そのものの意味が非対称**な場合に限る: 表紙のロゴパネル、テキスト+画像の説明パネルなど。これらは「どちらが強調されるべきか」が役割から自明であり、内容に依存しない普遍的な扱いのため決め打ちしてよい。複数要素が対等に並ぶ自由設計スライド(対等な要素の列挙、カードグリッド等)では、全セルを同じ淡色セルで統一し、特定の1件だけを固定でアンカー化しない——実際にどの項目が重要かは構成案の内容次第であり、位置で決め打ちすると内容と無関係な強調が毎回同じ場所に出てしまうため。
- **ドミナントカラーの役割**: プライマリカラー(`15803D`、深緑)がアンカーセル・半透明の章番号・キッカーバッジとして全レイアウトに反復して現れ、視覚の核を担う。淡色セル(`F3F3F3`)と白背景がその他の面積の大半を占め、プライマリカラーは常に少数の強調点(60-70%ではなく、"効く場所にだけ塗る"抑制型)として使う。
- **モチーフ**: 「番号をプライマリカラーの半透明大文字/小文字として塗りセルに重ねる」ことを反復するモチーフとする。セクション区切りの巨大な章番号(`addSectionSlide`)が主な実装例。対等な要素の列挙のように連番が意味を持つ自由設計スライドでも、この番号モチーフ(プライマリカラー・半透明・大きめのウェイト)をそのまま踏襲してよい。
- **ダーク/ライトの使い分け**: 表紙は右パネルのみ濃色、本文は白背景基調。終始ダークにはせず、濃色は常に「アンカーセル」という限定された面積にのみ使う(全面ダーク背景のスライドは持たない)。

## 装飾ルール

- **シャドウ**: 使わない。`rectRadius`・`shadow`のいずれも使用しない。
- **角丸**: 使わない。すべて`rect`(直角矩形)。
- **アクセントライン・帯状ストライプ**: 使わない(公式pptxスキルのAvoidリストにより全ブランド共通で禁止。`default`では過去に2度試して不採用にした経緯もある)。
- **キッカーバッジ**: 左上に置く、ブランドカラー塗り+白文字の小さなバッジ(`addKicker`ヘルパー、高さ`0.36"`)。全レイアウト共通の帯状ヘッダーは持たず、タイトルを添えたいスライドにのみ控えめに使う。バッジ幅はタイトル文字数から概算する(`estimateTextWidthInches`、全角1.15em/半角0.62em換算+安全係数1.15倍)。内容そのものが一目でわかるスライドではキッカーを出さなくてよい。
- **画像**: 実データを持たず、`addImagePlaceholder`ヘルパーによる破線枠+ラベルのプレースホルダーとして表現する。実画像の差し込みは常に公式pptxスキル側の責務。

## 余白グリッド

- `theme.spacing.marginX = 0.6"` / `marginY = 0.5"`: スライド全体の外周マージン。すべてのセル・テキストはこの内側に収める。
- `theme.spacing.gap = 0.3"`: セル間の標準ギャップ。複数区画を並べる自由設計スライドは必ずこの値(またはその倍数)を使う。
- キッカーがあるスライドのコンテンツ開始Y座標は `marginY + 0.36(キッカー高さ) + 0.16(ギャップ)` で決定論的に算出する(`contentTopY`ヘルパー)。ページ番号があるスライドのコンテンツ終了Y座標は `height - marginY - 0.3(ページ番号高さ) - 0.15(ギャップ)` で算出する(`contentBottomY`ヘルパー)。固定値を各関数にばらばらに埋め込まず、この2つのヘルパーに一元化している。

## フォントペアリング

- 見出し: `theme.fonts.heading`(Noto Sans JP)、本文: `theme.fonts.body`(Noto Sans JP)。
- 見出し・本文を同一ファミリーに揃え、`bold`の有無とサイズ差(`theme.text.*`)だけでヒエラルキーを作る。和文中心の資料で書体を混在させると可読性が落ちやすいため、1ファミリーに統一する方針をとる。

## 定型スライド一覧

`.agents/docs/fixed-primitives-contract.md`の契約と一致させること。

| # | 関数名 | 用途 | このブランドでの構成 |
|---|---|---|---|
| 1 | `addTitleSlide` | 資料冒頭の表紙 | 右側34%をアンカーセル(プライマリカラー全面塗り)にし、`logoLabel`を白文字でパネル下端に配置。左側66%にタイトル(36pt太字)・サブタイトルを下揃えで配置 |
| 2 | `addSectionSlide` | 章の導入 | 左側52%を淡色セルにし、`number`をプライマリカラー・不透明度45%の巨大文字(130pt)で重ねる。右側48%に章タイトル・補足説明 |
| 3 | `addClosingSlide` | 資料末尾の挨拶・連絡先 | 白背景に挨拶メッセージ(36pt太字)。`contactOrg`/`contactName`/`contactEmail`はすべて任意で、1件でもあれば淡色セルにまとめて表示(組織所属を前提にしない) |
| 4 | `applyChrome` | ページ番号等のランニング要素 | 右下に2桁ゼロ埋めのページ番号のみ(`text.caption`、`colors.textSecondary`)。帯状のヘッダー/フッターは付与しない |

## 自由設計スライドの指針

定型スライドに当てはまらない内容(標準コンテンツ・画像中心・テキスト+画像・対等な要素の列挙・指標の強調・比較・テーブル・引用・2×2マトリクス・プロセスタイムライン・強調メッセージ、`.agents/docs/fixed-primitives-contract.md`の自由設計カテゴリ参照)は、`pptx-build`が構成案の内容ごとに都度ゼロから設計する。その際も以下に従うこと。

- 上記「視覚言語」「装飾ルール」「余白グリッド」「フォントペアリング」に従う(角丸・影・アクセントライン不使用、淡色セル+限定的なアンカーセル、番号モチーフの反復)。
- 複数要素が対等に並ぶ自由設計スライド(対等な要素の列挙、比較のBefore/After、2×2マトリクス等)は、「構造そのものの意味が非対称であるときだけアンカーセルを使う」という視覚言語節の判断基準を踏襲する。例えば比較のAfter側や強調メッセージの単一メッセージは非対称が構造の意味そのものなのでアンカーセルでよいが、対等な複数要素の列挙(カード的な自由設計スライド)は淡色セルで統一する。指標の強調で先頭の指標を強調するかどうか、どの程度の非対称にするかは内容ごとに判断してよい。
- ページ番号は定型スライドと同様に`applyChrome(slide, theme, { pageNumber })`を呼んで付与し、独自にページ番号の描画コードを書かない(位置・書式の一貫性を保つため)。
- タイトルを添える場合は共通ヘッダー帯を作らず、`addKicker`相当の控えめなバッジスタイル(左上、ブランドカラー塗り+白文字)を踏襲する。

## 共通の実装ルール

- 色は必ず `theme.colors.*`、フォントは必ず `theme.fonts.*`、文字サイズは必ず `theme.text.*`、余白は必ず `theme.spacing.*` から取得し、固定値を直接埋め込まない。
- 画像は実データを持たず、プレースホルダー(ラベル付きの図形)として表現する。実画像の差し込みは常に公式pptxスキル側の責務であり、本デザインシステム生成スクリプトの範囲外。
- 実アイコン・実写真のレンダリング(`react-icons`/`sharp`等)には依存しない。

## テーマ変更時の再生成手順

1. `design-system/default/color-definition.json` を編集する。
2. `node design-system/generate-theme.js default` を実行し、`design-system/default/theme.js` を再生成する。
3. `node design-system/default/components.js` を実行し、`design-system/default/preview.pptx` を再生成する。
4. 生成された `.pptx` を開き、定型スライドすべてに変更後の配色が正しく反映されていることを目視確認する。
