# pptx-ssot

## この Skill の役割

調査結果 (`pptx-research` の対話結果、または自動推定された assumptions) を、固定フォーマットの Markdown ファイル `projects/<slug>/ssot.md` にまとめる。この Skill は pptx ファイルには一切触れない。純粋にドキュメント (Markdown) を書くだけであり、公式 pptx スキルにも依存しない。

`projects/<slug>/ssot.md` は、後続の `pptx-build` Skill が実際の資料を生成する際の**唯一の入力情報源**になる。ここに書かれていない内容は `pptx-build` 側では前提として使えないため、抜け漏れなく具体的に書くこと。`projects/<slug>/` は、この資料の構成案・完成資料・生成スクリプトを1箇所にまとめる作業ディレクトリで、ブランド(`design-system/<brand>/`)とは独立した命名軸を持つ (1つのブランドを複数の `projects/<slug>/` が使い回す関係)。

## slug の決め方

`<slug>` はディレクトリ名として安全な kebab-case (英数字とハイフンのみ、日本語不可) をユーザーに確認するか、資料タイトルから機械的に生成する (例: 「2026年度 新製品発表資料」→ `2026-new-product-launch`)。同名ディレクトリが既に `projects/` に存在する場合は上書きしてよいか確認する。

## 固定フォーマット

以下のテンプレートを**そのまま**使い、各セクションを埋める。セクションを省略せず、
情報がなければ「未定」「該当なし」等と明記する (空欄のまま黙って省かない)。

```markdown
# <資料タイトル>

## 対象読者
<誰が読む/聞くか。前提知識レベル。>

## 目的
<この資料で達成したいこと。読み手にどう動いてほしいか。>

## トーン・スタイル
<フォーマル/カジュアル、データ重視/ストーリー重視 等。>

## 章構成
1. <章タイトル> — <その章の要点1〜2文>
2. <章タイトル> — <その章の要点1〜2文>
...

## 各章の詳細
### 1. <章タイトル>
- 含めるべき内容・数値・エピソード:
- スライド枚数の目安:
- 参考にする既存資料/データソース(あれば):

### 2. <章タイトル>
...

## ボリューム感
<総スライド枚数の目安、発表時間の目安。>

## Assumptions
<pptx-research をスキップし、AI が自動推定した前提がある場合のみ記載する。
対話で全て確定した場合はこのセクションごと「該当なし」と書く。
記載する場合は、推定した項目とその根拠を箇条書きで残す。例:
- 想定読者: 社内の非エンジニア向け管理職 (依頼内容に「役員会向け」とあったため推定)
- 章構成: 課題→現状→提案→効果→次アクション の5部構成 (依頼内容の記述順から推定)>

## ビルド時の注意事項
<レイアウトの希望、避けたい表現、ロゴ・画像の扱い等、pptx-build に伝えたいことがあれば。
特になければ「特になし」と書く。>
```

## 手順

1. `pptx-research` の結果 (対話ログ、または assumptions 付きの自動推定結果) を集約する。
2. 上記テンプレートの各セクションを埋める。特に「章構成」と「各章の詳細」は、`pptx-build` がレイアウトを選ぶ際の主要な手がかりになるため、章ごとに扱う内容の性質 (比較なのか、時系列なのか、単なる説明文なのか等) が伝わるように書く。各章の「スライド枚数の目安」には、その章の中身のスライドに加えて、章の導入に使うセクション区切りスライドの分も**デフォルトで含めて**見積もる(全章で使う前提で1枚ずつ加算する)。これを含めずに見積もると、後工程 (`pptx-build`) が総枚数の目安を守ろうとして一部の章だけ区切りスライドを省略し、区切りページの有無が章ごとにばらつく原因になるため。
3. 「ボリューム感」の総スライド枚数・発表時間は目安であり厳密な上限ではない旨が伝わるように書く。`pptx-build` 側はこの目安の ±30% 程度までは前後させてよい前提とし、枚数を守るために内容やレイアウトの一貫性を犠牲にしないようにする。
4. `projects/<slug>/ssot.md` に書き出す (ディレクトリが無ければ作成する)。書き出し後、ファイルパスをユーザーに伝え、内容の確認を促す。
5. 確認が取れたら、`pptx-build` Skill でこの構成案から資料を生成できる旨を案内する。

## 注意事項

- `projects/*` は `.gitignore` されている (資料ごとの生成物のため)。コミットされないことをユーザーに伝えてよい。
- 本 Skill はテンプレートの体裁を保つことが最優先。自由形式のメモを書かない。
