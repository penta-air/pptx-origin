# pptx-research

## この Skill の役割

資料のテーマ・内容について、構成案(`projects/<slug>/ssot.md`)を書く前に発散/調査を行う対話フェーズ。公式 pptx スキルには一切依存しない (まだ pptx ファイルを扱う段階ではない)。

## モードの選択

対話モード(発散に付き合う)かスキップモード(発散を省略する)かは、**AI が情報量の多寡から推測してはならない**。ユーザーの依頼に明確なシグナルがあればそれに従う:

- 「壁打ちしたい」「相談しながら決めたい」等 → 対話モード
- 「この内容でそのまま進めて」「スキップして」等 → スキップモード

シグナルが明確でない場合、AI が判断を代行して決め打ちで進めてはならない。ユーザー本人に直接尋ねる。例:「対話しながら内容を詰めていきますか、それともいただいた内容から仮説を立てて一気に進めますか?」

## 対話モード: ユーザーが発散に付き合う場合

以下のような観点を、一度に全部聞くのではなく会話的に掘り下げる:

- **目的**: 何のための資料か (社内提案、営業資料、勉強会発表、投資家向け等)。
- **想定読者**: 誰が読む/聞くか。前提知識のレベル。
- **トーン**: フォーマル/カジュアル、データ重視/ストーリー重視、等。
- **章構成の方向性**: 大まかにどんな流れにしたいか (課題→解決→効果、現状→提案→ロードマップ、等)。
- **必須で入れたい内容・数値・エピソード**、逆に**触れなくていい範囲**。
- **参考にしたい資料・トンマナ**(あれば)。
- **ボリューム感**: 何ページくらい、発表時間の目安。

単に質問を重ねるだけで終わらせず、テーマに対して盛り込むと良さそうな内容・切り口の提案、章構成の叩き台の提示を積極的に行い、会話を広げることに徹する。事実確認・調査は対話の中で裏付けが必要になったタイミングで都度行えばよく、リポジトリ内の情報源(README・docs 配下等)に限らず、必要になればインターネット上の調査も行う。対話に先回りして大掛かりな調査をあらかじめ済ませておく必要はない。

会話全体を通じて、ユーザーの発言の背後にある意図を汲み取り、言葉にして返す(言語化する)ことを基本姿勢とする。これは踏むべき手順のひとつではなく、対話中つねに意識しておく振る舞い方である。

### 発散フェーズの終了

いつ収束すべきかの基準は明文化しない。AI が「この辺りで一区切りつきそうだ」と感じたタイミングで、収束するかどうかの選択肢をユーザーに明示的に提示する。例:

```
ここまでで章構成の骨子は見えてきたと思います。このまま収束して構成案の作成に
進めますか? それとももう少し掘り下げますか?
```

ユーザーが収束を選んだ場合のみ次工程に進む。掘り下げを選んだ場合は対話を続ける。

## スキップモード: ユーザーが発散を省略したい場合

ユーザーがスキップモードを選んだ場合、**沈黙のまま推測で進めてはならない**。以下の手順を踏む:

1. 与えられた依頼内容から、上記の観点 (想定読者・トーン・章構成など) を AI 自身が妥当な仮説として自動推定する。
2. 推定した内容を **明示的に「assumptions」として** ユーザーに提示する。例:
   ```
   以下を前提として進めます(違っていれば教えてください):
   - 想定読者: 社内の非エンジニア向け管理職
   - トーン: フォーマル、データより結論優先
   - 章構成: 課題提起 → 現状分析 → 提案 → 期待効果 → 次のアクション
   ```
3. ユーザーから訂正が入ればそれを反映し、なければそのまま `pptx-ssot` Skill に渡す。この assumptions のリストは、次工程で構成案の「Assumptions」セクションにそのまま引き継がれる。**黙って前提を決めて次工程に進むことは禁止**— 必ずユーザーの目に触れる形で可視化してから進める。

## 次工程への引き継ぎ

対話モード・スキップモードいずれの場合も、確定した (または assumptions 付きの) 情報一式を `pptx-ssot` Skill にそのまま渡せる形にまとめてから、そちらの Skill を呼び出すようユーザーに促す。本 Skill 自身は `projects/<slug>/ssot.md` を書かない。
